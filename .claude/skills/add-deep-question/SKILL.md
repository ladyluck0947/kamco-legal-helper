# 심화 테스트 질문 추가

사용자(작성자 임동욱)가 실무 상황을 주면, 그 상황을 판단하는 데 필요한 **실제 대법원 판례**를 찾아 `data/cases.json`에 원문 그대로 추가하고, `tests/questions.md`의 "심화" 표에 질문을 추가한다.

**가장 중요한 원칙:** 판례 번호·선고일·판단 내용과 정답 기준은 절대 기억으로 쓰지 않는다. 모두 국가법령정보센터 원문에서 가져오고, 원문 문장과 대조해 확인한다.

## 1. 상황 확인

- 사용자가 준 상황을 한두 문장으로 정리해 되묻고 확인한다. 상황이 여러 개면 하나씩 진행한다.
- 이미 `tests/questions.md`에 같은 상황이 있는지 먼저 확인한다.

## 2. 판례 찾기 (브라우저)

국가법령정보센터 판례 검색 결과를 브라우저로 연다. 검색어는 상황의 핵심 법률 용어 2~3개로 정한다.

```
https://www.law.go.kr/precSc.do?menuId=7&subMenuId=47&tabMenuId=213&query=<검색어>
```

페이지가 뜨면 아래 스크립트로 대법원 판례 목록과 판례일련번호를 뽑는다.

```js
await new Promise(r => setTimeout(r, 2500));
[...document.querySelectorAll('a[onclick*=precView]')]
  .map(a => a.textContent.trim().replace(/^\d+\.\s*/, '').replace(/\s+/g, ' ') + ' #' + a.getAttribute('onclick').match(/'(\d+)'/)[1])
  .filter(t => t.includes('대법원'))
  .slice(0, 10).join('\n')
```

- 검색어를 바꿔 2~3번 찾아보고, 후보를 5~10건 모은다.
- `data/cases.json`에 이미 있는 사건번호는 후보에서 뺀다.

## 3. 원문 가져오기

```bash
npm run cases:fetch -- <판례일련번호> <판례일련번호> ...
```

- 출력된 판시사항을 읽고, 상황 판단에 실제로 쓰이는 판례만 고른다.
- 정답 기준을 쓰기 전에, 고른 판례의 판결요지를 끝까지 읽는다. 출력 파일 위치는 명령 결과 마지막 줄에 나온다. 판결요지가 없는 판례는 판시사항만으로 판단한다.
- 판례가 "구 국유재산법" 조문을 쓰면, `data/laws.json`의 현행 조문과 내용이 같은지 반드시 확인한다. 다르면 질문에서 그 차이를 다룬다(예: 21번, 대부 만료 후 계속 점유).

## 4. 판례 추가

검색용 핵심어 파일을 임시 폴더(스크래치패드)에 만든다. 직원들이 쓸 쉬운 말도 넣는다.

```json
{ "2013다3576": ["한국자산관리공사", "캠코", "소멸시효 중단", "부당이득반환청구권 시효"] }
```

```bash
npm run cases:add -- <핵심어 파일 경로>
```

## 5. 질문 작성

`tests/questions.md`의 "심화: 여러 사정이 얽힌 상황" 표 맨 아래에 이어 번호로 추가한다. 형식은 기존 행과 같다.

| 칸 | 쓰는 법 |
|---|---|
| 질문 | 실제 직원이 묻는 말투. 상황의 사정(누가, 무엇을, 언제)을 담는다 |
| 정답 기준 | 결론 먼저("된다/안 된다/상황에 따라 다르다") → 판례가 든 이유. 판례 원문 표현을 따른다 |
| 근거 | `대법원 <사건번호>`, `국유재산법 제N조` 형식으로 적는다 (검증 도구가 이 형식을 읽는다) |
| 쉬운 말 | 법률 용어 없이 물었으면 ○ |
| 검토 | ☐ (작성자가 검토 후 ☑로 바꾼다) |

## 6. 검증

1. `npm run check:questions`: 근거가 data에 있고 정답 속 숫자가 원문에 있는지 확인한다. 모두 PASS여야 한다.
2. 정답 기준의 핵심 판단 문장(예: "소멸시효가 중단된다고 할 수 없다")이 판례 원문에 있는지 띄어쓰기를 무시하고 대조한다.
3. 개발 서버의 `/api/ask`에 새 질문을 보내, 결론과 인용 판례가 정답 기준과 맞는지 본다. 틀리면 결과를 사용자에게 그대로 알린다(질문을 바꿔 맞추지 않는다).

## 7. 마무리

- CLAUDE.md의 검증 루프대로 `npm run lint`, `npm run build`를 통과한 뒤 커밋한다. 커밋 메시지는 한국어 한 줄로 쓴다.
- 사용자에게 추가한 질문 표와 검증 결과를 초보자 눈높이로 알리고, 새 질문의 검토(☐→☑)를 부탁한다.
